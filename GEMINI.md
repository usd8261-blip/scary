# GEMINI.md — контекст проекта «До шести»

Этот файл — краткая карта проекта для ИИ-ассистента. Прочитай его целиком перед правками:
он экономит время и помогает не сломать геометрию дома, навигацию монстра и связку версий.
Пользовательская документация — в `README.md`.

---

## 1. Что это за проект

**«До шести»** — небольшой 3D-хоррор об одной ночи в доме. Игрок просыпается в спальне
(«комната 07»), слышит шаги за дверью и должен продержаться до 06:00. Теневой монстр
входит через входную дверь, ходит по коридору, кухне, рабочей комнате и спальне,
иногда проверяет укрытия. Игрок прячется, следит за шумом и дыханием и выполняет задания.

Есть три версии одного и того же проекта:

| Версия | Где лежит | Технологии | Статус |
| --- | --- | --- | --- |
| Браузерная (эталон) | корень репозитория | HTML + CSS + JS, Three.js r170, без сборки | актуальна, правки этой сессии здесь |
| Windows / ПК | `rust-pc/` | Rust + Bevy 0.14.2 | старая планировка, не синхронизирована |
| Android | `android-app/` | Gradle + WebView, копия браузерных файлов | ассеты не синхронизированы |

**Важно:** `android-app/app/src/main/assets/` содержит **копии** `game.js`, `index.html`,
`style.css`, `three.module.js` и модели. После правок в корне их нужно копировать туда вручную.
`rust-pc/src/main.rs` — отдельная реализация на Bevy, её нужно править отдельно.

## 2. Файлы

```
index.html                 разметка HUD, меню, экранные кнопки, importmap для "three"
style.css                  тёмный интерфейс, маски укрытий, мобильная раскладка

three.module.js            Three.js r170, локальная копия (интернет не нужен)

README.md                  описание для игрока

rust-pc/                   Cargo.toml, src/main.rs, assets/monster.glb, assets/fonts
```

**Нет** `package.json`, сборщика и тестов. Никаких новых npm-зависимостей не добавлять:
игра должна открываться с любого статического сервера.

## 3. Как запускать и проверять

**Браузер (основной способ):**

```bash
python -m http.server 8000
# открыть http://localhost:8000
```

`file://` не работает: ES-модули и `importmap` требуют HTTP.

**Проверка синтаксиса game.js** (Node не обязан быть в PATH):

```powershell
Copy-Item game.js game-check.mjs
node --check game-check.mjs      # проверяет синтаксис ES-модуля
Remove-Item game-check.mjs
```

**Визуальная проверка без ручного запуска.** Работает headless Chrome: рендер через
SwiftShader, консоль в stderr, скриншот в файл.

```powershell
chrome --headless=new --no-sandbox --use-angle=swiftshader --enable-unsafe-swiftshader `
  --user-data-dir=<временный профиль> --window-size=1100,700 --virtual-time-budget=5000 `
  --enable-logging=stderr --v=0 --screenshot=shot.png http://127.0.0.1:8000/index.html
```

Для отладки удобно временно добавить в `game.js` вывод в консоль (`console.log`) и вызов
`startGame()` сразу после `showOverlay(...)`, а камеру зафиксировать в `frame()`. Такие
правки делать только во временной копии проекта, не в рабочем файле.

**Rust-версия:**

```bash
cd rust-pc
cargo run --release
```

Сборка встраивает `rust-pc/assets/` в exe.

## 4. Как устроен game.js

Один IIFE `(() => { "use strict"; ... })();`, импортируются только Three.js и GLTFLoader.

### Ключевые константы

| Имя | Значение | Смысл |
| --- | --- | --- |
| `NIGHT_DURATION` | `210` | длина ночи в секундах реального времени |
| `MONSTER_RADIUS` | `0.34` | радиус монстра; используется при построении навигации |
| `ROOM` | `{minX:-6.5, maxX:20.5, minZ:-10.5, maxZ:10.5}` | внешние границы дома (и предел движения) |

### Таблицы данных (правятся в первую очередь)

- `taskSpots` — 10 заданий: `{name, hint, x, z, lookX, lookY, lookZ, hold, bonus}`.
  `x/z` — где стоять, `look*` — где висит янтарный маркер, `hold` — секунды удержания `E`,
  `bonus` — сколько секунд ночи «съедает» задание.
- `hideSpots` — 6 укрытий: `{id, name, x, z, y, exitX, exitZ, yaw, pitch}`.
  `id` обязан совпадать с CSS-классом маски (`.hidden-mask.<id>` в `style.css`).
- `patrolRooms` — по 3 точки на комнату: `bedroom`, `corridor`, `kitchen`, `workroom`.
  За одну вылазку монстр обыскивает одну комнату.
- `patrolPoints` — плоский список всех точек (используется для проверок).

### Геометрия

- `buildRoom()` — единственное место, где создаётся дом. Вспомогательные функции:
  `box(w,h,d,x,y,z,material,parent)` и `wall(x,z,w,d,id)`; `wall` сама добавляет коллайдер.
- `colliders[]` — массив прямоугольников `{minX,maxX,minZ,maxZ}`. Всё, во что нельзя входить:
  стены, мебель, шкафы. `collides(x,z,r)` = проверка границ `ROOM` + пересечение круга с прямоугольниками.
- Дверные проёмы — это **разрывы** между прямоугольниками стен, а не отдельный объект.
  Поэтому стена с дверью собирается из 2–3 кусков + перемычка сверху (без коллайдера).

### Навигация

- `nav` — кэш проходимой сетки: `{cell: 0.35, minX, minZ, cols, rows, walkable}`.
- `buildNavigation()` вызывается **один раз** сразу после `buildRoom()` (см. `buildRoom(); buildNavigation();`).
- `findPath(from, to)` — A* по этому кэшу, возвращает массив точек или `null`.
- Если добавить/удалить стену, нужно только пересобрать сетку (она строится из `colliders`);
  вручную сетку не править.

### Игрок

`player = {x, z, yaw, pitch, radius, stamina, breath, noise, hidden, flashlight, ...}`.
Старт — `(0, 2.6)`, взгляд на восток (`yaw = -Math.PI/2`), то есть на дверь спальни.
`updatePlayer()` — движение с коллизиями, бег, шум, дыхание; в укрытии движение отключается,
`Пробел` задерживает дыхание.

### Монстр

FSM в `updateMonster()`:

```
away → warning → entering → hunting ⇄ chase → leaving → away
```

- `away` — ждёт за входной дверью (`x=8, z=10`), таймер `random(9,14)`.
- `warning` — стук в дверь, 3.4 с, сообщение «Шаги остановились у входной двери».
- `entering` — идёт от двери в коридор (`moveMonsterDirect`).
- `hunting` — обыск: комната выбирается в `beginHunt()` (`monster.room`), цель — `choosePatrolTarget()`.
  С вероятностью 0.55 монстр сначала идёт к случайному укрытию (`chooseSearchTarget()`),
  доходит и «прислушивается» 1.8 с (`searchWait`), затем продолжает обход.
  Замечает игрока (`canSeePlayer`) и шум; при `awareness >= 0.85` переходит в `chase`.
- `chase` — бежит к `lastSeen`, ловит при касании; через `lostTimer` теряет игрока.
- `leaving` — идёт по маршруту к входной двери (`moveMonster`), дверь открывается.
  Через 12 с или при застревании уходит в `away`.

Важные поля: `awareness`, `exposure`, `searchTarget`, `searchWait`, `targetIsSearch`,
`room`, `path`, `pathIndex`, `repathTimer`, `stuck`.

Застревание: в `moveMonster()` при `moved < 0.001` монстр слегка сдвигается в свободную
сторону, сбрасывает путь и перепланирует. Не убирать этот предохранитель.

### Остальное

- `updateTasks()` — удержание `E` у задания, начисление `bonus` к `elapsed`.
- `interact()` — войти/выйти из укрытия, подсказки.
- `updateExposure()` — если монстр рядом с укрытием и игрок не задерживает дыхание,
  растёт `exposure`; при 1.0 — поражение.
- `updateHUD()` — часы, задания `N/10`, полоски сил и воздуха, индикатор опасности, подсказки.
- `updateScene()` — анимация монстра, дверей, маркеров, ламп, пыли.
- `SoundEngine` — весь звук синтезируется через Web Audio, аудиофайлов нет.
- `frame()` — `requestAnimationFrame`, `dt` ограничен `0.034`; при `dt = 0` монстр не двигается
  (защита от ложного «застревания»).

## 5. План дома (координаты, метры)

Пол дома: `x ∈ [-6, 20]`, `z ∈ [-10, 10]`, высота стен 3.5. Ось `+x` — на восток, `+z` — на юг.

| Комната | Интерьер | Двери |
| --- | --- | --- |
| Спальня (старт) | `x -6..6`, `z -4..4` | в коридор: `x=6.08`, `z -0.75..0.75` |
| Коридор | `x 6.16..10`, `z -10..10` | входная дверь: `z=10.16`, `x 7.1..8.9`; на кухню: `x=10.08`, `z -6..-4.4`; в кабинет: `x=10.08`, `z 4.4..6` |
| Кухня | `x 10.16..20`, `z -10..0` | из коридора (см. выше) |
| Рабочая комната (кабинет) | `x 10.16..20`, `z 0.16..10` | из коридора (см. выше) |

Кухня и кабинет разделены стеной `z=0.08` (от `x=10` до `x=20.16`).
Монстр входит в дом с юга через коридор и дальше расходится по комнатам.

### Укрытия

| id | Где | Выход |
| --- | --- | --- |
| `bed` | под кроватью в спальне | `(-3.55, -0.82)` |
| `wardrobe` | шкаф в спальне | `(4.65, -1.55)` |
| `closet` | шкаф в коридоре, у западной стены | `(7.6, 6.8)` |
| `counter` | под кухонной стойкой у северной стены | `(13.1, -8.4)` |
| `pantry` | кладовка у восточной стены кухни | `(18.4, -2.2)` |
| `cabinet` | шкаф в кабинете у западной стены | `(11.7, 8.2)` |

Маски укрытий: `.hidden-mask.bed`, `.wardrobe`, `.closet`, `.cabinet`, `.counter`, `.pantry`
в `style.css`. Новый `id` без CSS-класса = прозрачный экран без эффекта «ты внутри».

### Задания

Спальня: окно, розетка/стол, засов двери. Коридор: входная дверь.
Кухня: мойка, холодильник, обеденный стол. Кабинет: компьютер, сейф, бумаги на полках.
Суммарный бонус всех заданий ≈ 116 с при ночи 210 с — баланс осознанный.

## 6. Инварианты: что нельзя ломать

1. `buildNavigation()` — строго после всей геометрии. Новые стены/мебель после неё
   не попадут в маршруты монстра.
2. Любая новая мебель должна добавлять `colliders.push(...)`, иначе игрок и монстр
   будут проходить сквозь неё.
3. Дверные проёмы — только разрывы в стенах; не ставить коллайдер поперёк проёма.
4. `hideSpots[].id` ↔ CSS-класс маски.
5. Точки заданий, укрытий и патруля должны быть достижимы: проверять `findPath` из спальни
   и отсутствие коллайдера в самой точке (радиус игрока 0.28).
6. `MONSTER_RADIUS` участвует в построении сетки: менять его — только вместе с пересборкой.
7. `dt = 0` не должен считаться застреванием (см. проверки в `moveMonster`/`moveMonsterDirect`).
8. Тексты интерфейса — на русском, стиль существующих подсказок сохранять.
9. Никаких внешних запросов и новых зависимостей: всё лежит в репозитории.

## 8. Быстрый чек-лист после правок

1. `node --check` для `game.js`.
2. Открыть игру, пройти из спальни в коридор, на кухню и в кабинет; проверить, что все
   дверные проёмы проходимы и не «режут» игрока.
3. Спрятаться в каждом укрытии: экран должен затемняться маской, `E` — выходить.
4. Дождаться монстра: сообщения «у входной двери» → «вошло в дом» → шаги по комнатам.
5. Убедиться, что задания выполняются и счётчик `N/10` растёт.
6. Если менялись корневые `game.js`/`index.html`/`style.css` — скопировать их в Android-ассеты.
